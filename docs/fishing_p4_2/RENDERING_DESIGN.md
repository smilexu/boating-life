# Fishing P4.2 — 绘制与数据映射

## 数据来源

`FishFinderDisplay` 通过既有 `FishResourceManager.get_fish_finder_sensor()` 获取同一个 `FishFinderSensor`，只调用 `get_last_scan()`、`get_scan_history()` 和历史覆盖接口。新扫描 ID 到来时复制历史快照；绘图代码不查询学校、不改变扫描频率、不修改 P2 随机状态。

P4.1 保留 `scan_runtime_seconds`、`bottom_valid`、`bottom_depth_below_transducer_m`、`echoes` 等字段。每个鱼群回波的 `target_depth_below_transducer_m` 和底部深度都相对换能器，不是海图 LAT，也不是水面以下深度。图表纵轴顶部为换能器基准 0 m，底部为当前显示量程。

## 历史与绘制

- 横坐标按 `now - scan_runtime_seconds` 映射到 60 秒窗口；最新记录靠右。
- 传感器按自身 3 Hz 节拍新增记录；UI 读取新扫描的轮询间隔为 0.2 秒，图表平滑刷新上限约 18 Hz。刷新只移动时间网格/旧回波位置，不生成额外样本。
- 历史扫描列有界，沿用 P4.1 的传感器容量。窗口变化仅重新映射既有样本。
- 海底只连接有效且间隔不超过 1 秒的相邻列。无效底部或无效深度清空连接状态，形成缺口。海底用亮边、暖色回波带和向下衰减带表现。
- 每条实际学校回波绘制为中心较亮、外围较弱的橙黄聚合亮斑。亮度由 `echo_strength` 决定，面积使用 `echo_width_m` 显示代理。相邻扫描中同一 `school_id` 最多用淡线连接，间隔超过 1 秒则不连。
- 不足以构成连续回波时只显示亮斑；没有跨扫描“补画”鱼弧，也不显示鱼种和精确鱼数。

## 自动量程

候选档为 5、10、20、30、50 m。基于有效底部深度 `d` 计算需求 `d + max(1 m, 0.08d)` 并选取最小可容纳档。向更大档立即切换；向小档收缩要求底深低于现档 70% 且连续保持 3 秒。无效底部不会改变量程。若所需深度超过 45 m，50 m 只扩展显示坐标，不扩展传感器探测范围。

量程变化会对全部历史列使用同一个新纵轴重绘，因此历史图保持统一的深度比例。量程之外的鱼群回波不绘制。

## UI 和性能

迷你图右下角按当前可见 Viewport 比例布局；展开图居中，显示面积随 Viewport 调整。两个模式共用同一图表和历史数据。关闭后停止自身刷新，重新打开从传感器已有历史恢复。

图表直接使用 `Control._draw()`，没有额外 SubViewport、Shader、GPU Compute、纹理缓存或每像素节点。每次重绘遍历有限的最近历史列和其中的实际回波；隐藏时不进行 UI 重绘。开合、重开和视口重排只影响 UI。

## 层级处理

Boat HUD 所在 CanvasLayer 在展开期间暂时提升到第 90 层，处理当前项目中诊断 CanvasLayer 遮挡展开面板的问题。缩回迷你、关闭或退出场景时恢复初始化时的层级。最高的游戏菜单层仍在其上方。该层级交互在 Headless 测试中验证，并在本机 Forward+ 展开画面中检查。
