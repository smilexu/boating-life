# Fishing P4.1 — 最终审查

## 交付结论

P4.1 声呐数据源已接入现有 `FishFinderSensor`。空水域会给出有效空回波列；真实 Authority 学校只有在当前换能器向下声束及距离/深度条件内才进入本列。新列保留可绘制的目标深度、位置、强度、学校规模代理以及同列海底数据。

## 关键行为

- 扫描原点跟随当前活动船；偏移为传感器 Inspector 可调的船体局部值，默认 `(0, -0.55, 0)` m。帆船模式使用实际活动帆船刚体。
- 海图 LAT 水深、动态水面高度、换能器世界高度和换能器至海底距离分别记录。海图无数据时不创建鱼回波，底距以无效标记和 -1 哨兵返回。
- 默认 10° 半锥角、220 m 斜距上限、45 m 最大水深、3 Hz 扫描、至少 60 秒历史（默认 180 列）。停船照常扫描；历史固定容量。
- 使用 P2 的 Authority 空间索引；每个学校最多一条聚合回波。回波强度由 population 和声束位置/距离确定，无随机数。
- 保留 `scan()`、`get_last_scan()`、`get_scan_history()`；F3 手动扫描继续可用，诊断现在报告列有效性、回波、探头至底部距离、历史和扫描配置。
- P2/P3 的生成、恢复、鱼数、运动、钓鱼候选/概率和结算均未修改。

## 通过的验证

- P4.1 扫描几何、深度基准、确定性回波、历史环形淘汰、停船节拍、船型切换和无效底部数据测试：PASS。
- P2 拖钓/Authority 结算和 Fish Finder 集成回归：PASS；扫描前后 Authority revision 与 Encounter RNG 状态相同。
- Headless editor 项目导入/脚本类注册及 `git diff --check`：PASS。
- Forward+ 声呐屏幕与实际船体换能器摆位：NOT RUN。

## P4.2 使用提示与限制

P4.2 可将每个 `echoes` 数组画作一列，将 `scan_runtime_seconds` 用于水平滚动，将 `bottom_depth_below_transducer_m`/`bottom_valid` 画作底部回波。Gain 应只改变绘制亮度阈值或强度映射，不要重新查询或改变候选学校。

P2 目前只有学校锚点、总鱼数和活动深度，没有每条鱼位置或学校真实空间外形。因此当前“一个学校一个聚合亮斑”是真实学校来源，但回波宽度/群体档是明确标注的游戏化显示代理，不能解释成水声测量值。换能器偏移目前由共享传感器配置；若各船型的换能器实际位置不同，后续需给船型提供各自偏移并在活动船切换时读取。实际屏幕布局和探头安装位置需要在 Forward+ 场景中确认。
