## 测试环境与方法

测试船为 `res://scenes/boats/SailingBoat8m.tscn`（Nordic 28），由 SailboatLab 实例化真实 `RigidBody3D`，复用当前帆力、浮力、龙骨、船舵、船体阻力和 AUTO Trim。runner 通过已有实际船舵目标角接口闭环保持 TWA，不锁定刚体朝向、不直接写入航速或角速度。发动机关闭，水流为零；WindField 使用固定风向和 seed，关闭阵风与风向随机变化。WaveSampler 仍由船体正常查询，但本地波浪幅值为零，形成静水条件。

正式判定窗口沿用 P1 Profile：最少预热 60 s、稳定判断窗口 30 s、稳定后采样 30 s、单工况上限 300 s。速度稳定、航向误差、TWA 误差、舵饱和、侧滑、横倾等都从实际物理快照采集；失败状态保留原始 SOG 和失败原因，不补零、不连成有效曲线。

每个工况重新设置相同初始位置、姿态和零速度，真实风向固定为 180°（正南来风）；带符号目标 TWA 区分左右舷。无水流时 `STW = SOG`。VMG 使用采样到的世界水平速度向量对真实风来向（迎风）或风去向（顺风）投影；正迎风 VMG 表示朝风源方向的速度分量，正顺风 VMG 表示朝风去方向的速度分量。

### 480 Hz 与 1/60 s 步长

P1 smoke/P2 执行器用 `Engine.physics_ticks_per_second = 480`、`Engine.time_scale = 8`。在 Godot 4.7.2 中，预期模拟物理步长为 `8 / 480 = 1/60 s`。runner 逐物理帧检查刚体回报的 `physics_delta_s`，结果必须与 Profile 的 `1/60 s` 相差不超过 0.0005 s；每条工况记录观察到的步长及最大误差。加速倍率只改变墙钟运行速度，不放大单步物理积分；模拟秒数和墙钟秒数分开记录。headless CPU 饱和使实际吞吐低于理论 8 倍，因此报告会用工况实测墙钟耗时，不把配置倍率说成实测加速比。

配置指纹涵盖 Godot 版本、目标条件、Profile 存储值与资源路径、船型场景文件、选定船型物理 Profile，以及帆船气动/水动力/浮力/导航、WindField、WaveSampler、AUTO Trim、发动机和 Polar 测试相关脚本源。恢复时逐项校验指纹，拒绝混用配置。

### 航速与风速趋势及物理合理性

观测到的最大稳定 SOG依次为0.431、1.332、2.387、3.499和4.631 kn（TWS 4、8、12、16、20 kn），随风速平顺增加。稳态横倾也随风力增加，稳定侧滑保持有限，舵角没有在有效点饱和；近迎风失败则集中且在左右舷镜像。未见 NaN/Inf、速度发散、无解释的速度尖峰或负风速。就该游戏级模型的内部一致性而言，趋势合理、结果可解释。

目前模型在轻风下航速偏低，且低于约70°–90°区域难以产生稳定正迎风VMG；这个限制来自整套帆力—龙骨—船舵—自动操帆闭环的当前表现，Polar扫描不能单独证明是哪一个物理子系统造成。20 kn真风下约4.63 kn的最大稳定速度接近项目的游戏级巡航参考量级，但不能外推成实船性能。没有用这些观察反向修改帆装或物理参数。
