# 画质设置与性能基线

## 结论概览

- 运行环境：Godot 4.7.2 stable、Forward+ / Metal 3.2、Apple M2 Pro（Apple8）、macOS Darwin 24.6 arm64。目标设备 Apple M4 本轮不可用，不能把以下数据外推为 M4 结果。
- 游戏提供 100%、75%、67% 的 3D 分辨率档位；F3 面板可即时切换。缩放只作用于 3D buffer，UI 继续使用窗口输出分辨率。低于 100% 时启用 Godot FSR 2.2。
- 实际测量在 Godot VSync 关闭、Engine.max_fps=0 下完成。3440×1440 窗口模式达到或超过 30 FPS；外接屏全屏被 Godot 报告为 6880×2880，性能优先档也只有约 20–24 FPS，没有达到 30 FPS。
- GPU 粒子开关对测量帧率没有稳定、显著的负面影响；关闭云层通常提升约 3–6 FPS。没有独立 GPU 时间数据，不能定量拆分海面、体积云或粒子的 GPU 成本。
- 短样本存在明显波动，尤其 1920×1080 基准；下方数字是一次运行的观察结果，不是性能保证。

## 首次推荐和持久化

QualityManager 在没有已保存画质时，只推荐一次初始档位，并将推荐结果写入 user://quality_settings.cfg。判断综合使用显卡 / Apple Silicon 型号类别、处理器核心数、当前窗口尺寸，以及已连接显示器中最大报告像素尺寸。分辨率不是唯一判断条件。首次推荐后，改变窗口尺寸、全屏状态或 FPS 上限不会触发重新推荐。玩家在 F3 面板手动选择任何画质后，保存的档位一直优先于推荐值。没有实时动态分辨率。

| 档位 | 3D 分辨率缩放 | 1920×1080 估算内部尺寸 | 3440×1440 估算内部尺寸 | 主要现有画质参数 |
| --- | ---: | ---: | ---: | --- |
| 画质优先 | 1.00 | 1920×1080 | 3440×1440 | 4096 阴影，SSR 48 步，SSAO，云 160 主步 / 12 光照步，四级海面 LOD |
| 平衡 | 0.75 | 1440×810 | 2580×1080 | 2048 阴影，SSR 32 步，较轻 SSAO，云 128 / 10 步，四级海面 LOD |
| 性能优先 | 0.67 | 1286×724 | 2305×965 | 1024 阴影，关闭 SSR / SSAO，云 96 / 8 步，三级海面 LOD |

低分辨率档通过根 Viewport 的 scaling_3d_scale 设置，并在小于 1 时使用 SCALING_3D_MODE_FSR2。Godot 4.7 文档说明 FSR 2.2 用于上采样 3D buffer，1.0 才是原生分辨率；Viewport scaling 仅支持 Forward+ / Mobile。UI 与实际窗口像素分别读取，不以逻辑尺寸推断 framebuffer。[Godot Viewport 4.7](https://docs.godotengine.org/en/4.7/classes/class_viewport.html) · [Godot Window 4.7](https://docs.godotengine.org/en/4.7/classes/class_window.html) · [Godot DisplayServer 4.7](https://docs.godotengine.org/en/4.7/classes/class_displayserver.html)

## 测试环境与方法

- 在 scenes/SimpleParticleWake.tscn 复用主场景进行对照。船以 7 m/s 巡航；同一天气和摄像机初始位置。GPU 粒子开 / 关、云开 / 关、三个画质档完整组合。每个组合预热 3 秒、测量 5 秒。
- 基准临时关闭 VSync 并设 Engine.max_fps=0；HUD / 应用帧率上限不参与测量。平均 FPS 由测量帧数 / 实际采样秒数计算；平均帧时间由相同样本计算（1000 / 平均 FPS）。
- GPU 毫秒不可用：Godot 当前可读监视器没有提供本轮可用、可靠的独立 GPU frame time。不能用帧时间冒充 GPU 时间。
- 桌面活动、窗口焦点和云合成器状态会影响短时读数；测试顺序没有随机化，也没有重复多轮统计置信区间。因此特别是 1920 窗口数据只能作为方向性基线。

### Godot 显示与 HiDPI 探测

图形测试查询了 DisplayServer.window_get_size()、screen_get_size()、screen_get_scale()、刷新率，以及根 Viewport 大小和缩放因子。项目显式开启 display/window/dpi/allow_hidpi=true。

| screen index | screen_get_size() | scale | 刷新率 |
| ---: | ---: | ---: | ---: |
| 0 | 3456×2234 | 2.0 | 120 Hz |
| 1 | 6880×2880 | 1.0 | 165 Hz |

测试请求在第二屏创建 3440×1440 窗口，窗口 framebuffer 与根 Viewport 实测为 3440×1440。切换全屏后，Godot 将输出 / 根 Viewport 报告为 6880×2880（19.8 MP），是预期 3440×1440（4.95 MP）的 4 倍像素数。当前不能从 Godot 输出确认 macOS 的显示器型号或显示设置为何使这个屏幕回报 6880×2880；在目标 Samsung 屏上复测时，请先确认 macOS“显示器”中的实际模式，并记录 F3 诊断面板的窗口、显示器和 Viewport 像素数。

外接屏全屏三档估算内部 3D 尺寸：100% 为 6880×2880、75% 为 5160×2160、67% 约 4610×1930。即使 67% 仍约 8.9 MP，明显高于 3440×1440 输出应有的 4.95 MP。

## 3440×1440 窗口（外接屏）实测

窗口 framebuffer 和根 Viewport 实测为 3440×1440；显示器 screen_get_size() 报告 6880×2880。每格依次为尾流关闭、GPU 粒子开启。

| 档位 | 内部 3D 尺寸 | 云开 | 云关 |
| --- | ---: | ---: | ---: |
| 画质优先 | 3440×1440 | 60.63 / 16.49；60.12 / 16.63 | 82.73 / 12.09；76.92 / 13.00 |
| 平衡 | 2580×1080 | 58.08 / 17.22；58.29 / 17.16 | 67.66 / 14.78；65.50 / 15.27 |
| 性能优先 | 2305×965 | 73.39 / 13.62；70.31 / 14.22 | 85.28 / 11.73；87.70 / 11.40 |

这一轮中性能优先整体读数最高；平衡档并未持续快于画质优先，说明 FSR2 上采样和当前插件 / 渲染负载的成本需要在更多轮次中复核。所有档位超过 30 FPS；没有做长时稳定性验证。

每格依次为尾流关闭、GPU 粒子开启。

| 画质优先 | 6880×2880 | 17.03 / 58.719；16.73 / 59.770 | 22.89 / 43.682；22.41 / 44.615 |
| 平衡 | 5160×2160 | 15.62 / 64.010；15.73 / 63.554 | 18.45 / 54.208；18.48 / 54.111 |

在该实测全屏输出中，没有一个档位达到 30 FPS。性能优先是三档中较快的一档，GPU 粒子影响约在测量噪声范围，关闭体积云多获得约 3–6 FPS。关闭云仅用于性能诊断，本项目没有将其设为默认。

## GPU 尾流对照与验证边界

- 测试时 GPU 粒子容量为 240；7 m/s 巡航的稳态活跃粒子估算约 135。精确活跃数量不读取 GPU 回传。尾流开启时渲染器计数比关闭时约多 1 个 Draw Call。
- 3440 窗口和 6880 全屏各档中，开启粒子没有稳定降低 FPS；变化约在 -0.3 到 +2.4 FPS，方向随组合变化。与旧动态 Mesh 方案没有在本轮重新跑同场景数据。
- 离线状态检查覆盖 STOP、LOW、CRUISE、FAST、S_TURN、STOP_FADE，粒子估算数为 0、33、135、206、136、0；停船关闭发射后既有粒子按生命周期消散。
- 无可用 GPU 毫秒、独立海面 / 云成本、长时稳定 FPS、GPU / CPU 瓶颈百分比。未在 Apple M4 上实测。关闭云的测试只用于量化相对成本，不构成建议默认关闭。
- FSR2 缩放运行 Sunshine Clouds 2 和 GPU 粒子场景时，没有遇到着色器或 Compositor 初始化错误；没有完成逐帧图像审查，因此 FSR2 的拖影、细节损失和云层闪烁仍需人工查看。
- Godot 进程退出时出现 Sunshine Clouds 2 管线 / Compute / Texture RID 泄漏警告；运行期间基准无脚本错误或渲染设备错误。该第三方资源释放警告仍未修复。

## 手动在目标 Samsung 3440×1440 上复测

1. 在 macOS“系统设置 → 显示器”确认外接显示器当前模式；目标应是实际 3440×1440 输出，而不是窗口逻辑尺寸。记录 HiDPI 缩放设置。
2. 运行：godot --path . res://scenes/SimpleParticleWake.tscn -- --display-benchmark-3440-windowed，验证窗口 framebuffer / Viewport 报告 3440×1440。
3. 全屏手动切换后，先从 F3 诊断信息记录窗口 framebuffer、screen pixels、HiDPI scale 和 Viewport pixels。如果 screen 像素数与预期不符，先确认系统显示模式再测。
4. 运行：godot --path . res://scenes/SimpleParticleWake.tscn -- --display-benchmark-screen=1 --display-benchmark-fullscreen。命令关闭 VSync 和 FPS 上限，并自动测试 3 个画质 × 云开关 × GPU 尾流开关。
5. 在目标 M4 上重复 1920×1080 窗口与 3440×1440 全屏测量，每档至少三轮；同时检查画面和 FSR2 时间稳定性。自动脚本输出分辨率、帧率、帧时间、Draw Calls 和粒子估算数；GPU 毫秒当前不可用。

基准命令不写入玩家持久化画质选择；玩家设置在测试后继续保留。

## 正式 WakeSystem 最终版本复测（2026-10-15）

使用最终泡沫 Shader 与 Profile 配置，通过 `SimpleParticleWake.tscn` 中的正式船体 WakeSystem 对照开 / 关。条件：画质优先、云开启、晴天、7 m/s、相同船尾镜头；VSync 关闭、`Engine.max_fps=0`，每状态预热 8 秒、采样 6 秒。设备为 Apple M2 Pro / Metal 3.2 / Forward+，不是目标 M4。screen 1 报告 6880×2880 / scale 1.0，窗口 framebuffer 和 Viewport 分别确认是 1920×1080 或 3440×1440。

| 输出窗口 / 配对 | 尾流 | 平均 FPS | 平均帧时间 | 最短 / 最长帧 | 平均 Draw Calls | 活跃粒子估算 |
| --- | --- | ---: | ---: | ---: | ---: | ---: |
| 1920×1080 | 关闭 | 120.00 | 8.333 ms | 8.200 / 8.333 ms | 86.9 | 0 |
| 1920×1080 | GPU 粒子 | 119.34 | 8.380 ms | 5.037 / 16.833 ms | 87.9 | 121 / 240 |
| 3440×1440 | 关闭 | 61.04 | 16.382 ms | 15.700 / 16.667 ms | 96.0 | 0 |
| 3440×1440 | GPU 粒子 | 60.31 | 16.581 ms | 15.928 / 17.284 ms | 97.0 | 126 / 240 |

本轮最终配对中，GPU 粒子开启后 1920 平均低 0.66 FPS、3440 平均低 0.73 FPS；两种窗口都只多约 1 个 Draw Call。1920 读数接近屏幕 120 Hz；不能据此推断目标 M4 或长期帧率。3440 的这组 6 秒样本超过 30 FPS，但没有长时间压力测试。独立 GPU 毫秒不可用。

同一外接屏设置的额外短样本曾落在约 58–61 FPS，且一次出现 63 ms 尖峰；更早的预热后样本也曾到约 145 FPS。窗口、输出像素与质量设置都确认相同，但桌面活动和 GPU / 合成器状态没有锁定，因此绝对 FPS 波动明显。开关尾流的配对差值始终小于系统间波动，暂时没有证据表明 WakeSystem 是主要性能瓶颈。

图形退出时持续出现 RenderingDevice RID 泄漏警告；运行期间未见 WakeSystem / 泡沫 Shader / Metal 报错。无法仅凭该警告归因于 WakeSystem，它也可能来自 Sunshine Clouds 2 Compositor。
