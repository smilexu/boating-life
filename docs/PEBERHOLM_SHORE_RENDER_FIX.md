# Peberholm 岸线渲染修复（2026-10-18）

本轮实际 Forward+ 对照推翻了此前“正常材质已经显示岛顶，因此只需裁掉海水”的判断。此前海面遮罩露出来的灰绿色大片是水下封底，真正的岛顶被背面剔除了。

## 运行时来源与测量

通过独立网格着色、海面隐藏以及只切换剔除方向的实验确认：

| 画面部分 | 实际 Mesh / 资源 | 世界坐标与证据 |
| --- | --- | --- |
| 修复前的灰绿色大片 | `OresundRegion/CoastTransitions/PeberholmClosedUnderbody` 的底面 surface 1 | Y=-2.50m。把整个封闭侧体临时染蓝后，大片区域变蓝；顶面染绿但保持 CULL_BACK 时没有出现绿色。 |
| 真正的岛顶 | 三个 `Terrain_chunk_*` 原始 ArrayMesh 中的 448 个三角形 | X=-1507.533..1717.467m，Z=9851.353..12431.353m，Y=+1.25..+3.00m。只把局部材质切换为 CULL_FRONT 后完整出现。 |
| 浅灰色宽带 | `CoastTransitions/OresundCoastTransition` 内 Peberholm 的 1212 个三角形 | 上缘 Y=+1.25m，下缘 Y=-0.30m，水平宽约 3.32m。独立染红后对应原来悬空的带；真正岛顶恢复后，它成为连续附着的护岸。岸坡自身使用正常 CULL_BACK，未改其几何或剔除设置。 |
| 额外伸进水里的细线 | `OresundBridge/PeberholmOutline/Peberholm_OSM_Coastline_Outline` | ImmediateMesh LINE_STRIP，Y=+1m。这是测绘轮廓调试线，不是桥梁构件。 |
| 原海面裁切边缘 | `sea_water.gdshader` 的 2048² R8 OSM mask discard | 边界约 1.58×1.26m/纹素；裁切使用 OSM 线，不是实际岸坡水线。 |

实际岸坡水线由加载网格的三角面与 **Y=0** 求交获得，没有拿最近采样顶点代替。808 个交点（含相邻三角形共享点）到 OSM 线距离为 **0.043..14.368m**；504 个交点在 OSM 多边形之外。最近截图 GPS 55.58997N / 12.77726E 的实测水线点为 X=1704.068m、Z=12264.460m，与该 GPS 平面位置相距 20.678m。

大块错位锯齿来自两套不同的轮廓与水下封底被露出，并非单纯 2048² 遮罩分辨率不足。原始低面数岸线本身也有折角，这轮未重塑轮廓。

## 实施

- 复用已有网格分区代码，从三个已加载源块中分出 Peberholm 的现有面。所有面的位置、顺序、法线和顶点色按原值复制；未改变原始地形文件、岛顶高程或封闭侧体。
- 只给 Peberholm 顶面使用 **opaque / CULL_FRONT** 的正常顶点色材质，补偿现有源面绕序与 Godot 正面约定的相反关系。其他地区继续使用原材质。
- 删除上一轮 OSM 海面裁切纹理的生成、uniform 和 fragment discard。完整岛顶现在正常写深度，海水与已有岸坡直接按实际几何相交；波浪移动时水线随深度遮挡变化，不再与另一条静态遮罩线竞争。
- 岸坡与封闭侧体继续使用原网格和原材质。没有新建、扩大或重建岛体。
- OSM 调试线默认隐藏，仅在 F3 岛屿颜色诊断开启时显示。桥梁结构、位置和 LOD 未改。
- F3 开关现在在同一份 Peberholm 顶面上切换正常/诊断材质，关闭后保持正确的可见面。

## 实际验证

Godot 4.7.2、Apple M2 Pro、Metal Forward+，加载真实 `scenes/main.tscn`。

- 逐面字节比对：三个原始地形块与其“岛顶分区 + 其余分区”的三角形坐标和绕序完全相同；岸坡诊断分区也通过相同比对。
- 顶面仍为 448 面，Y=+1.25..+3.00m；F3 开/关后正常材质恢复；闭合侧体 Mesh 实例未替换。
- 将船的 MotionRoot 放在截图 GPS 附近，使用海上相机与正常材质检查。HUD 与船模在验证器中临时隐藏，便于辨认岸线。
- 在距实测水线约 35m 的近岸位置检查斜向视角。
- 临时通过现有天气调试接口设置波浪强度 1.5，分别检查 t=5s / 12s，随后恢复；没有更改正式天气或波浪资源。
- 全岛俯视检查仅在验证相机中关闭雾，以免数公里视距的雾遮住证据；游戏正式雾参数未改。
- 这些画面中，顶面完整，原先游离的宽带已成为附着岸坡，未再出现海面裁切缺口或露出的水下封底。
- 编辑器扫描与验证器均返回 0，没有脚本编译或海面 Shader 编译错误。退出时仍出现 ParticlesShaderRD / RID 释放警告，未在本轮处理。

复现命令：

```sh
godot --path . --script tools/verify_peberholm_shore.gd
```

必须使用图形渲染，验证器拒绝 headless。输出在 `.godot/peberholm_shore_check/`，正常结束自行退出；若断言失败则 45 秒超时退出，避免留下后台游戏窗口。正常人工观察仍可用 Shift+F5 循环到 Peberholm 端；F3 岛屿颜色诊断开关保留。

## 保留项与验证边界

岛体保持灰盒，原有多边形折角、单色护岸仍然可见；没有进行岸线重塑。全岛俯视图中海上更大的方格色带来自原导航水深纹理着色，不是地形开边或海面裁切缺口，本轮未修改该数据或着色。没有做 Windows 渲染或长期环岛航行测试，不能据这几个机位宣称整个岛岸所有视角均已人工验收。


## 后续：岛顶是否被水平截断（彩色模型对照）

针对截图 GPS 55.58998N / 12.77681E 附近再次运行 Forward+。本次只在独立验证实例中放置 5 根 8×8×30m 的不透明彩色立柱，底部贴在原顶面三角形中心。位置从近处延伸至岛内远处，底部 Y 分别为 1.792、1.792、2.724、2.443、1.833m；没有向正式场景添加模型。

- [低机位彩柱对照](peberholm_shore_fix/test_columns_low.png)：5 根柱体均显示，没有沿可疑水平线被横切。
- [升高机位彩柱对照](peberholm_shore_fix/test_columns_raised.png)：同一批柱体完整分布在连续岛顶上。
- [实际网格边界低机位](peberholm_shore_fix/actual_boundary_low.png)、[俯视边界](peberholm_shore_fix/actual_boundary_overhead.png)：粉色线来自原顶面三角形仅出现一次的边，非 OSM 偏移轮廓。共 202 条外边，Y 全部为 +1.25m，单边长度 0.986..122.711m；远处“水平截断线”与远岸外边相符。
- 玩家相机 far=80000m，本次验证相机 far=30000m，岛体位于该范围内；没有发现这一位置的相机远裁切或内部地形缺面。

结论：本次可疑水平边缘对应远侧岛岸。低视角、同色灰盒和低起伏使它看起来像平板被横切。这个结论限定于所检查的 Peberholm 位置；并不代表灰盒美术已经自然。现有长直线和规则护岸仍是外观局限。在保留岛顶/岸坡几何的本轮约束下，没有为了消除这种观感而变形岛体、改变高度或新增装饰。测试实例已退出，彩色柱子不留在正式游戏中。
