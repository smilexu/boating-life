# P2.2 MacBook 双屏 FPS 诊断

## 结论

用户提供的 F3 截图确认：Main 游戏全屏运行在 MacBook 内屏，窗口屏幕索引为 `0 / 2`，屏幕 API 尺寸为 `3456×2234`，窗口 API 尺寸为 `3456×2160`。截图显示 2 个屏幕；结合用户说明与原测试环境，按双屏连接场景记录。当前 F3 只显示索引和尺寸，没有显示器名称，因此不能从截图独立确认第二屏的品牌型号。本机系统显示信息只返回 Apple M2 Pro GPU，没有列出显示器；当前 CUA 也只能看到 Godot 编辑器窗口，不能操作该 Main 游戏窗口。用户截图可作为目标环境的实际测量；分辨率 A/B 已完成 30 秒筛查，云层及其他隔离 A/B 尚未测。本轮未实施正式画质或渲染优化。

后续截图显示已经完成 30 秒采样：当前正式基线为 **0.67 FSR2、19.4 FPS、平均帧间隔 51.66 ms、P95 83.80 ms**。同期 F3 快照为 24 FPS / 41.67 ms，`TIME_PROCESS` 52.11 ms，Draw Calls 665、可见物体 1922、图元 3,300,197；窗口 3456×2160、屏幕 3456×2234、索引 0/2、内部 3D 估算 2316×1447。帧率上限 60 FPS、VSync 开启、GPU Apple M2 Pro (Apple8)。测试画面为帆船手动掌舵，航向 061°；天气为阴天、云量 91%、波浪强度 1.55，场景显示有效风 4.5 m/s、来向 240°。这组结果低于 30 FPS 目标约 10.6 FPS，P95 超过 33.3 ms 参考值约 50.5 ms。

用户随后在同一内屏、同一场景切到 0.50 FSR2 并完成 30 秒筛查：**19.8 FPS、平均帧间隔 50.57 ms、P95 83.06 ms**；内部 3D 估算 1728×1080。相对 0.67 基线，平均帧间隔缩短 1.09 ms（约 2.1%），P95 缩短 0.74 ms（约 0.9%），FPS 增加 0.4。快速筛查显示降低渲染比例的收益很小，不支持继续大幅降低分辨率；因此未追加 0.75。两张 30 秒截图里的航向和天气相近，但波浪强度从 1.55 变为 1.50，Draw Calls / 可见物体 / 图元也有变化（665/1922/3,300,197 → 629/1886/2,917,175），说明场景没有完全静止；差值只作为低收益信号，不据此精确归因或声称严格可重复。

前一张截图的 19 FPS / 52.63 ms 是采样开始前的单帧快照；更早的 22.9 FPS / 43.61 ms / P95 79.90 ms 也是另一时刻的读数。船型、镜头与场景状态并不完全相同，因此都不作为 A/B 对照，只把后续 30 秒样本作为本轮新基线。

## F3 指标与测试入口

F3 中原标为“脚本”的读数来自 `Performance.TIME_PROCESS × 1000`。Godot 将该监视器定义为单帧处理时间；它不是脚本独占耗时，也不是 GPU 执行时间。因此，先前看到的 61.81 ms / 53.65 ms 如果来自这个字段，应理解为当时的单帧处理监视器值，不能据此归因到 GDScript。字段现已改名为“Godot 单帧处理”。[Godot Performance 文档](https://docs.godotengine.org/en/4.7/classes/class_performance.html)

F3 性能区现在复用同一性能面板，增加：

- 仅改变根 Viewport 3D Rendering Scale 的 0.50、0.67、0.75 FSR2 选择器；不切换画质 Profile。常规“画质 / 3D 分辨率”档会同时改变阴影、SSR、SSAO、云和海面 LOD，不适合单变量 A/B。
- 30 秒筛查 / 60 秒复核，以及“开始 / 重置性能采样”按钮。改变设置后固定场景并预热，再按按钮计时。采样期间保持 F3 面板打开，所有组都这样做。
- 体积云开关，只切云渲染资源，天气模拟继续运行。
- 海面片元隔离开关。它保留海面网格、顶点位移和 WaveSampler，只用简单片元输出替代常规海面片元着色；它仍保留现有透明混合渲染模式，因此测得的是常规片元着色路径的差值，不等同完整海面渲染成本。
- 岸边建筑 / 港口装饰开关，只隐藏 Malmö 城区和 Copenhagen Harbor 下的 `VisualInstance3D`。碰撞、地形、节点逻辑不变。
- 海底植被视觉开关，只隐藏已生成的海草 MultiMesh 根节点，生态数据和生成链路继续运行；不清空实例。

结果会显示平均帧间隔、P95、平均 FPS，以及 Draw Calls、可见物体和图元。F3 另显示窗口屏幕索引、屏幕数量和 API 尺寸；Godot 不提供足够信息在此报告里将索引可靠映射为“内屏”或“三星外屏”，需在 macOS“显示器”设置中确认索引对应关系。

### 多项视觉开关同时关闭的探索样本（不可归因）

用户随后同时关闭了多个 F3 视觉诊断项。首个 30 秒样本为 **24.3 FPS、平均帧间隔 41.08 ms、P95 81.78 ms**；同屏读数为 Draw Calls 948、可见物体 2260、图元 1,473,778，3D Scale 0.67 FSR2。用户更正此前的船型识读：截图是帆船手动驾驶，并非动力船。随后同样全部关闭的帆船样本为 **20.6 FPS、平均帧间隔 48.50 ms、P95 80.76 ms**；Draw Calls 550、可见物体 1804、图元 1,712,338，航向 341°、波浪强度 1.50。样本间平均帧间隔相差 7.42 ms，P95 相差 1.02 ms；与 0.67 基线相比，航向 / 镜头状态也不完全一致（基线航向 061°，波浪强度 1.55）。这些仅作为多项关闭的探索记录，不计入上表的独立 A/B 结果，不能证明云层、海面、建筑或植被中任何单项的收益。

分辨率 A/B 显示 0.67→0.50 仅有约 1.09 ms 平均帧间隔改善，像素负载不是当前唯一或主导瓶颈的证据增强，但仍需云层与视觉隔离测试后再排序。尚无法区分 CPU、GPU 像素、GPU 顶点、额外 Pass 或同步等待各自占比；也没有证据证明此前窗口性能从 60 FPS 降到 30 FPS 是某次提交导致的。

## 建筑 LOD 只读检查

- `OresundRegion` 在场景中使用 `mesh_lod_index = 0`；`oresund_region.gd` 加载时从离线 LOD 列表选择一个网格，没有运行时距离切换。
- `OresundBridge` 有按距离更新的近 / 中 / 远 / 隐藏 LOD，脚本设置的更新间隔为 0.5 秒。
- Malmö 城区由少量 GLB 建筑与静态场景网格组成，当前 `malmo_city_district.gd` 没有运行时建筑 LOD 切换。
- Copenhagen Harbor 的灰盒装饰由多个 Box / Cylinder / Sphere MeshInstance 生成，没有 LOD；Malmö Harbor 场景关闭其灰盒港口物件，但包含 Malmö 城区。
- 阴影实际覆盖比例、材质批次数和远处物件渲染量本轮没有在 Forward+ 中采样。尚无依据重做 LOD 或合批。

海底植被使用 MultiMesh 分组；管理器统计数据中包含植被批次和图元数，但本轮没有采得画面中的实际数量或性能差值。按任务约束，若目标机测试显示成本不明显，应停止深入调查。

## 目标 Mac 执行步骤

1. 保持三星外屏连接，在 macOS 显示器设置里确认内置 Retina 屏幕与外屏仍处于扩展模式。将 Main 游戏窗口移到内屏并全屏。打开 F3，确认屏幕尺寸、窗口屏幕索引 / 数量、窗口模式、3D Scale、帧率上限和 VSync；将索引映射到 macOS 显示器名称。
2. 固定船位、镜头、天气、时间与船舶状态，帧率上限使用 Unlimited。先按用户基线 0.67 运行 30 秒筛查。
3. A 已完成 0.67 与 0.50 的 30 秒筛查，收益很小，当前测试建议恢复 0.67；不追加 0.75。若之后要提高数据可信度，可在完全固定场景下对 0.67 与 0.50 各跑 60 秒复核。
4. 先固定 Nordic 28 帆船、船位、船首向、镜头、天气和所有诊断选项。云层开启时，海面片元隔离关闭、建筑显示、海底植被显示，预热后采样 30 秒；随后只关闭云层，再按同样流程采样。之后 C、D1、D2 也各自与同一视觉基线成对测试，每次只切一个选项。仅对收益明显或波动大的组再做 60 秒；每组记录平均 FPS、平均帧间隔、P95，D1 / D2 另记 Draw Calls、可见物体、图元数。
5. 按节省的平均帧耗时毫秒数排序。F3 的 TIME_PROCESS 不是 GPU 计时；若需要区分 GPU Pass，应另用 Xcode Instruments 的 Metal System Trace。不要用 `1000/FPS` 作为 GPU 执行时间。

## 代码检查与限制

- `godot --headless --path . --editor --quit`：退出码 0；发现仓库已有重复 `.translation` UID 警告。Headless 环境无法执行 Metal 图形验收，并输出无法保存用户级 Godot editor settings 的提示。
- `godot --headless --path . scenes/main.tscn --quit-after 2`：退出码 0，Main 场景及新增诊断控件脚本加载；无渲染设备，因此不代表 Forward+ Shader 画面验收。退出时有 RendererDummy 资源泄漏提示。
- A 分辨率项已运行 30 秒筛查；B 云层、C 海面、D1 建筑 / 港口、D2 海底植被尚未运行。尚未做画质对比或性能优化；全屏稳定 30 FPS 状态仍未验证。

本轮修改只增加可复现的开发诊断入口，并纠正 F3 指标名称；没有修改海浪采样、浮力、船舶物理、天气模拟或正式画质默认值。当前最大瓶颈未知。下一步应先在目标双屏内屏全屏环境完成 A/B，按毫秒收益决定是否继续优化。
