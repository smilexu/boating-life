### 循环与素材检查

- 循环素材的自动首尾分析发现渐出、渐入或边界电平/波形差异。工具保留基础 OGG，并额外生成 `_loop.ogg` 供运行时优先循环；副本通过尾部与头部 1 秒三角淡化交接，时长相应减少 1 秒。未经试听不能保证每个过渡都比原版更自然，可直接把 `OM02_loop.ogg` 等改为基础 `.ogg` 进行听感比较。
- T01–T03 的渐入与衰减尾音保留；T01 检测到约 1.15 秒低电平开头，T03 检测到约 28.96 秒处的短安静段。没有将其当作待删除静音。
- 对 W01/W02 是否混有雨声、雨声素材是否含雷、海浪是否含发动机等内容，FFmpeg 数字分析无法可靠分类。本轮没有人工试听，以上项目需玩家试听确认。
- Godot 在隔离的临时项目成功导入并读取全部 23 个 OGG，确认返回 `AudioStreamOggVorbis`，且运行时可在副本上开启循环。后续主项目运行发现动态加载资源尚未进入主项目的 Godot 导入数据库；已通过 `godot --headless --path . --editor --import --quit` 执行 Godot 自身的导入流程，生成标准 `.import` 记录。运行时加载失败原因和修复记录见下方“运行时资源导入补充”。

## 音频架构

### 总线

总线在客户端运行时按名称创建并连接到 `Master`，重复启动管理器不会重复添加同名总线：

```text
Master  (AudioEffectLimiter: threshold -2 dB, ceiling -0.5 dB)
├── Music
├── Weather  (风、雨、雷)
├── Ocean    (海面环境、船体拍浪)
└── Engine
```

0–100 滑块先转为线性增益，再换算为 dB；0% 使用总线静音。混音层音量有上限，不持续改动 Master 增益。

### 当前音轨及驱动

| 声音 | 使用资源 | 运行时输入及混音 |
|---|---|---|
| 发动机 | `assets/sfx/processed/OM02_loop.ogg` | 读取 `BoatController.get_engine_audio_state()`。动力代理基于实际油门或自动巡航目标；音量随动力变化，pitch 限于 0.86–1.13，并平滑追踪。熄火代理关闭时淡出。 |
| 风 | W01、W02 循环副本 | 采样船边 WindField，并减去船速向量得到相对风速；约 4–14 m/s 等功率平滑交叉，整体目标增益上限 0.72。 |
| 雨 | R02、R03 循环副本 | 读取 `WeatherStateController.get_precipitation_visual_state()` 正式 mm/h；0 mm/h 静音，R02/R03 在约 4–15 mm/h 平滑交叉，整体目标增益上限 0.72。雨粒子调试覆盖不会改正式雨声。 |
| 海面 | SW01、SW02、SW03 循环副本 | 从 WaveSampler 读取当前生效的波浪资源和强度，按现有波幅参数计算混音指标；不另做波浪采样或公式。F3 海况过渡会反映到声音。SW01 保留安静底层，整体上限 0.68。 |
| 船体拍浪 | S01、S02 循环副本 | 读取浮力组件已有的升沉/俯仰/横摇速度；不增加 WaveSampler 查询。S01 为轻微底层，S02 随受浪代理增强，最大目标增益 0.30。 |
| 雷 | T01、T02、T03 单次 | 只响应 LightningEventController 实际闪电事件信号。使用事件位置与摄像机位置计算距离及 3D 声像；云地闪电使用海平面附近的 strike 位置，云内闪光则使用云层位置。T03 `<1200 m`、T02 `<3500 m`、更远使用 T01。 |

所有持续混音每帧仅平滑现有播放器音量；风、雨和海况输入约每 0.2 秒采样。Thunder 使用固定 6 个 `AudioStreamPlayer3D` 复用，不为每个事件创建 Timer 或播放器。

### 雷声传播与音乐压低

雷声等待时间为 `距离（米）/343` 秒，使用单调运行时钟排队。强雷暴时只对 Music 总线增加短暂增益衰减，不写入音乐开关或玩家设置；正式雷暴预报当前只提供有/无符号，控制器采用保守强度 0.32，对应约 -3.48 dB。强雷暴的本地测试覆盖可到 -4.5 dB；近雷播放时额外最多 -1.5 dB，总衰减限制在 -6 dB。音乐总线在约 1.25 秒内平滑变化。

### 发动机状态限制

当前船舶控制器没有独立点火/熄火机制或实测 RPM。音效读取的只读代理把未停航、未靠泊的动力船视作怠速运行，并以油门/自动巡航需求估算动力。R 调试面板提供独立“熄火”测试值。增加真正的驾驶员点火控制需要单独的船舶交互任务，本轮没有改动推进逻辑。

## 菜单、设置与本地测试

- ESC 设置页保留背景音乐开关，增加天气、海浪/船体、发动机三个 0–100% 滑块。
- 默认值：音乐开启、天气 68%、海浪/船体 72%、发动机 62%。改动立即生效，并保存到共用 `user://settings.cfg` 的 `[audio]` 区段；各管理器在写设置前重读配置，避免覆盖彼此键值。
- R 面板沿用现有快捷键，增加本地音效预设：静水熄火、平静巡航、中雨、强降雨加大浪、强雷暴；显示输入值、各循环层目标/实际增益及音乐 duck。关闭 R 面板或按“恢复正式音效输入”会清除天气和船舶两侧的音频覆盖。
- 音频覆盖只影响本地播放测试，不修改 WeatherStateController、WindField、WaveSampler、船舶状态或存档。R 面板里原有雷电按钮仍发送实际本地雷电测试事件，所以雷声会按距离延迟播放。
- `get_audio_diagnostics()` 同时提供程序可读状态。Dedicated server 与 headless 渲染环境不创建本地音频播放器。

### 运行时资源导入补充（2026-10-21）

首次在主项目直接运行时，日志显示 `EnvironmentAudioManager could not load W01/W02/R02/R03/SW01/SW02/SW03` 及 `BoatAudioController could not load OM02/S01/S02`。素材文件本身可播放，但新增音频尚未由主项目 Godot 扫描导入，动态加载器因此无法找到资源，导致这些播放器没有创建。已执行 Godot 原生导入流程；之后 `ResourceLoader` 对发动机、船体、海浪和风声的 8 个循环 OGG 均返回 `AudioStreamOggVorbis`，图形主场景启动日志不再出现上述音频加载失败警告。原有游戏实例需要重新运行，才能创建这些播放器。新增测试在 `tests/test_audio_sfx.gd` 中检查这 8 个资源，当前 79 项断言通过。声音的实际听感仍需在重启后的游戏中人工确认。

## 玩家人工验收步骤

1. 用 Godot 编辑器打开项目，等待 `assets/sfx/processed/` 下新 OGG 完成自动导入，然后运行 main 场景。
2. 按 ESC → 设置，调天气、海浪/船体、发动机音量；确认 0% 静音以及关闭重开项目后音量恢复。
3. 按 R，滚动到“动态音效测试”。依次试听平静巡航、中雨、强降雨+大浪、强雷暴；点“静水/熄火”确认发动机淡出。
4. 在 R 面板触发近/中/远云地闪电，听延迟、方位与远近素材；确认音乐在强雷暴期间仅轻微压低，离开测试后恢复正式状态。
5. 关闭 R 后确认正式天气/船舶输入接管。再试听每个 `_loop.ogg` 与基础 `.ogg` 的接缝，尤其是 OM02、风声及海浪；报告任何雨/雷/发动机串入情况。
6. 在 Apple M2 及 Windows 独显机器用相同画面/分辨率记录无雨、强雨、大浪和雷暴下的帧时间；本报告没有虚构这些数据。
