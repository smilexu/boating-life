# 海面坡度场与光照阶段诊断

本轮最早观察到的异常位于片元 `micro_slope`，进入最终法线和水面 BRDF 之前。已找到能定量复现一个屏幕坡度跳变的浮点格点哈希运算顺序敏感性。实际 Windows Shader 的指令重排尚未通过 SPIR-V 反汇编核实，因此将其列为强证据支持的根因机制，而非已证明的驱动或 Godot Bug。

## 输出定义与范围

S：`R=0.5+micro_slope.x/0.5`，`G=0.5+micro_slope.y/0.5`。固定对称范围 `[-0.25,+0.25]`；任何分量越界时 B=1，否则 B=0。没有逐帧归一化。它显示原始梯度合并值，尚未乘以 detail_strength 或 sun_glitter_intensity。

L：`max(dot(normalize(N_world),normalize((0.7,0.35,0.62))),0)`，固定范围 `[0,1]`。N 来自正常 Gerstner+细节混合；输出绕过水面 BRDF、Fresnel、阴影、水深颜色与浅水透明。

在排除天空、船体的底部海面 ROI `(0,700)–(1920,1080)` 中，共 729600 像素，没有蓝色裁剪标记。按线性映射与 sRGB 输出反解，X 约为 `[-0.1611,0.1115]`，Z 约为 `[-0.1421,0.1379]`。这是 8-bit PNG 的近似估计，不能当作高精度 GPU 读回。

数学保守界限：单层梯度分量不超过 1.875，FBM 导数系数之和为 `0.62+0.27×2.03+0.11×4.11=1.6202`。考虑旋转及两组输入，任一世界坡度分量的保守界限约 0.675；并非实际画面一定达到该范围。固定映射在本次 ROI 内未饱和。

## 图像结论

S 已有直线边界和块状坡度变化，L 保留较弱的相同结构。正式水面有更明显的明暗对比，但由于正式输出还包含环境反射、雾、色彩和不同的色调映射，这三张图不能单独量化 BRDF 的放大倍率。可以确认：正式 BRDF 不是异常最早出现的位置。

## 一个边界的定量追踪

S 图像素 `(1700,751)` 到 `(1701,751)`，PNG 反解坡度由 `(-0.041057,0.048601)` 跳到 `(-0.120909,0.082694)`，差为 `(-0.079851,+0.034093)`。

使用 F9 相机和实际 P_DEG，离线重建连续曲面及附近 1m 网格三角形。两像素落在同一个重建三角形内，位置只改变约 7mm；CPU float32 梯度保持连续。该重建没有读取 GPU 坐标缓冲，仍有渲染浮点与三角形实现差异的限制。

A 组最高频输入恰好由 `(5271.5356,9770.0010)` 跨到 `(5271.5371,9769.9971)`，即跨越 y=9770 的整数边界。Value Noise 的 quintic 解析梯度在此应连续，共享边两端的哈希值必须一致。

对同一格点，分别计算 `(cell+offset)*constants` 与 `cell*constants+offset*constants`，用 float32 执行后得到：

| 共享格点 | 先形成格点坐标 | 分配乘法后 |
|---|---:|---:|
| (5271,9770) | 0.33984375 | 0.8115234375 |
| (5272,9770) | 0.5498046875 | 0.0830078125 |

`water_hash` 的多次乘加把细小的舍入差异放大，最终 `fract` 又可能越过整数边界。把这些共享端点差异代回原始 FBM 权重、梯度公式与旋转，预测世界坡度跳变为 `(-0.079210,+0.032559)`，与截图观测差的向量距离约 0.00166。

这不是仅凭图案猜测：相同格点的等价浮点表达式能产生严重不同的哈希，并定量复现实际边界跳变。它强烈支持“共享格点哈希在不同求值路径下失去一致性”。具体 GPU 是否采用了这里模拟的分配乘法、FMA 或其它等价重排，尚未直接证实。

## 静态坐标与精度审查

- `world_coordinates` 来自位移后的世界顶点；`detail_position` 直接取世界 XZ，没有局部化。此处约 12km，float32 ULP 约 0.98mm。
- 旋转和最高频层使部分噪声坐标接近 10000，ULP 也约 0.001 噪声单位。单纯坐标 ULP 不能直接证明米级块状边界。
- varying 未声明 flat/noperspective，源码采用默认连续插值。没有证据证明插值本身就是故障来源。
- `floor/fract` 用于格点选择，属于噪声定义；若共享格点哈希一致，梯度在边界应连续。没有其它显式坡度整数化。
- 最具体的风险在 `water_hash` 的浮点乘加和最终 fract：共享格点通过不同 cell+offset 路径计算，数值对运算顺序高度敏感。Mac 实际行为未验证，不能据此归咎 Windows 驱动。

这一机制也能解释为何换 Simplex、改变格点尺度仍保留边界风险：两种噪声共享同一个浮点哈希；尺度调整只改变边界位置。低频层产生更大空间范围的边界，细节法线和正式光照使其可见。
